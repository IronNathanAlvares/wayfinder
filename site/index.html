Portfolio project · LangGraph · Ireland

An ordered plan with prerequisites, and a refusal to answer the questions that need a person.

Somebody who has just arrived faces about forty administrative tasks across housing, healthcare, schooling, welfare and legal status. They are spread across agencies that do not talk to each other, and they have hard prerequisites nobody tells you about. Getting the order wrong costs weeks.

Everything on this page was produced by running the real system and recording what it said. Nothing here is a mockup, and nothing here is written by hand. How that works, and what it leaves out.

The plan is a graph, not a list

Ask a general model what to do after arriving and you get a competent bulleted list that is close to useless, because it does not tell you which items you cannot start yet and what specifically unblocks them. Here the ordering is computed from a dependency graph, so it is the same every time and it can be checked.

Amara arrived on 1 August 2026 and applied for protection three days later. She is sleeping rough while she waits for accommodation, and she has a seven-year-old with her.

Every question takes one of five routes

The route is decided before anything is generated. Two of the five never reach a language model at all: a crisis is answered from a dated directory of real phone numbers, and a question about somebody's entitlements is handed to a named caseworker.

The handoff is the product

This is the part the design optimises for. An entitlement question stops the graph, and what reaches the caseworker is the question, a short summary of the situation and nothing else. She answers once. The system relays her words rather than restating them in its own voice, because doing that would launder a person's judgement into machine confidence.

The pause is durable. It is a row in a database, not a variable in memory, so a caseworker can answer on Thursday a question asked on Monday and the process can restart in between. There is a test that kills the process mid-pause and resumes it in a different one.

What it will not do, and why that is structural

Each of these is enforced by the shape of the graph rather than by asking a model nicely, and each has a test.

No eligibility determinations

"Do I qualify for X?" is not answered. There is no edge in the compiled graph from a determination question to a generated answer, and a test deletes the human node and proves generation becomes unreachable.

No generated content in a crisis

A crisis response is read out of a dated directory of verified numbers. A model improvising during somebody's emergency is unacceptable, and a model is not needed to read out a phone number.

No claim without a dated source

Anything not resting on a cited span is removed rather than softened. "You may be entitled to X" is still an entitlement claim, and it is worse than silence because it sounds like permission to plan around it.

No refusal that leaves you stuck

Every refusal names somebody else who can help, with a real number. Somebody refused and given nothing goes and asks a system with no such scruples, and gets a confident wrong answer instead.

The compiled graph, drawn from the real thing

Read off the compiled LangGraph rather than sketched. Determination questions reach composition only through handoff; crisis and decline are terminal.

The number the project actually turns on

The crisis screen has to catch somebody saying they have nowhere to sleep, or that they have taken something, when they never use those words. It was measured on a held-out corpus of 320 crisis turns and 200 near misses, written before anything was run against it.

A hand-written pattern list is not enough

It scores 1.000 on the corpus it was tuned against and 0.100 on a held-out one. The design assumed a deterministic screen could reach 0.99. That assumption was tested and it is false.

Four rounds of prompt work moved it by 0.04

Rewriting the self-harm section from the published clinical taxonomy, giving every category equal emphasis, screening each category in its own call, and unioning three samples. Between them: 0.85 to 0.93.

Changing the model moved it by 0.12

Same prompt, same items. Self-harm recall went from 0.648 to every one of 54 items. Four rounds of varying everything except the model had produced a confident conclusion about the model nobody moved.

What these numbers are not

  • The gate is still unmet. The 95 percent lower bound is 0.955 against a target of 0.99. A perfect 320 out of 320 on a 320-item split would bound at only 0.9907, so certifying 0.99 needs a corpus about three times this size.
  • The corpus has one author. The same person wrote the pattern list, every prompt and all four held-out splits. That is the largest limitation here and no procedure fixes it. It needs a few hundred real messages, or a couple of hours from somebody who has read them.
  • Recall is not the only cost. The stronger model fires on 13 of 200 near misses against the weaker model's 7. Roughly double. Worth it in a screen whose whole asymmetry is that a false positive costs somebody a list of helplines they did not need, but worth saying.

How this page works, and its security

This is a recording, and it is built so that it cannot be anything else.

It makes no network requests

Not one, after the page loads. The data is a JavaScript file, not a fetch, so the Content-Security-Policy can set connect-src 'none'. The page cannot send anything anywhere, which is checkable in any browser's network tab.

No API key exists here

No model is called from this page, so there is no key to leak, no endpoint to abuse and no per-visitor cost. The screening that produced these results ran offline against a held-out corpus.

No dependencies, no build step

Hand-written HTML, CSS and JavaScript. No framework, no bundler, no package manager, so there is no third-party supply chain to audit and nothing that can be compromised upstream.

Nothing about you is collected

No analytics, no cookies, no fonts or scripts from anybody else's server. The only thing stored is your light or dark preference, in localStorage, on your own machine.

Content is inserted as text

Every value from the data file reaches the page through textContent rather than innerHTML, so a string containing markup renders as characters instead of executing. Belt and braces given the data is generated, but it costs nothing.

Headers are set, not assumed

vercel.json in the repository sets the CSP alongside HSTS, X-Content-Type-Options, Referrer-Policy, a restrictive Permissions-Policy, and frame-ancestors 'none' against clickjacking.

What this page deliberately does not show

  • The crisis example is one the pattern list catches. The recordings run with no model, so the turn shown is a direct one. The measurements section is where the hard cases live, and it says plainly that the pattern list alone catches about one in ten.
  • No live input. You cannot type your own question, because answering it would need a model call, a key, and a per-visitor cost. A live version would also need authentication on the caseworker queue, which does not exist yet.
  • This is not a deployed service. It is a portfolio project. Nobody's real circumstances have ever been through it, and the ethics document in the repository is explicit about the distance between the two.
